### 3.1 Expression grammar and judgment

PE-TSE-EXPR-V2 replaces V1. It preserves Engineering[252]'s primitive and derived canonical value encodings, definition/component tables and combined-cycle rejection, except as replaced here. Its grammar changes tuple syntax to make its type explicit:

```text
tuple-expression = "tuple(" type-id "," expression "," expression *( "," expression ) ")"
```

Every expression synthesizes exactly one type under judgment `P; D; C; Γ ⊢ e => τ`; checking `e` against expected type `τ` succeeds only when synthesis returns the identical type ID. Rules are closed:

- `literal(τ,b)` synthesizes τ after exact canonical decoding;
- `arg(n)` synthesizes the nth declared input type in Γ;
- `ref(c,side)` synthesizes component c's canonical type;
- `tuple(τ,e1,...,en)` requires τ to name one declared TUPLE, exact arity, and each ei to check against its corresponding declared field type, then synthesizes τ;
- `equal(e1,e2)` requires both operands to synthesize the identical type and returns BOOL3;
- `not`, `and`, `or` require BOOL3 operands and return BOOL3;
- `member(e,d)` requires d to be a SET definition and e to have its element type, then returns BOOL3;
- `apply(d,...)` checks exact declared inputs and returns d's output type;
- each status expression returns BOOL3.

No rule selects a tuple by structural shape. Duplicate tuple shapes are permitted because the explicit tuple type ID distinguishes them. Every nested tuple is independently typed. A definition is admitted only when its complete expression synthesizes its declared output. Every grammar-valid expression has either one derivation or none; ambiguity is invalid. Evaluation is structural, left-to-right, finite and terminating after the combined definition/component graph passes Kahn acyclicity. `PE-TSE-SET` is the only reserved built-in and remains limited exactly as in Engineering[252].
