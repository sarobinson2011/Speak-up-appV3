## Technical Implementation

### ZK Circuit (Circom)

**File:** `zk/v3-groth16/circuits/sign_petition.circom`

**Specifications:**
- Depth-10 Merkle tree (supports 1,024 members)
- Poseidon hash function (ZK-friendly)
- Nullifier: `hash(memberSecret, petitionId, SIGN_DOMAIN)`
- Constraints: 6,220
- Public inputs: 3 (nullifier, petitionId, membershipRoot)
- Private inputs: 21 (memberSecret, membershipPath[10], membershipIndices[10])

**Public Signal Order (CRITICAL):**
```javascript
publicSignals[0] = nullifier       // Output comes first!
publicSignals[1] = petitionId      
publicSignals[2] = membershipRoot  
```

### Smart Contracts

**Groth16Verifier.sol:**
- Auto-generated by snarkjs from proving key
- Size: 7,837 bytes (7.7KB)
- Gas cost: ~389,997 to deploy
- Verification gas: ~259,062 per proof

**Groth16VerifierTest.sol:**
- Wrapper contract for testing
- Tracks successful verifications
- Emits `ProofVerified` event with public signals

### Proof Generation

**Command (Node.js):**
```bash
cd zk/v3-groth16
node test-golden-proof.js
```

**Output:** `golden-proof.json` with:
- Proof (pi_a, pi_b, pi_c)
- Public signals
- Solidity calldata (formatted for cast/foundry)
- Original inputs (for debugging)

**Proof Size:** ~256 bytes (standard Groth16 on BN254)

```bash
node test-golden-proof.js

```

### Phase 2: Deploy to Aurora
```bash
cd contracts
forge script script/DeployGroth16.s.sol:DeployGroth16 \
    --rpc-url https://testnet.aurora.dev \
    --account dev-deployer \
    --sender 0xf8f8269488f73fab3935555fcddd6035699dee25 \
    --broadcast \
    --legacy \
    --skip-simulation
```

### Phase 3: Verify Contracts
```bash
./verify.sh 0xE70E2cFA4a4272B39918A45BA1F067676CCf8c11 src/v3/Groth16Verifier.sol:Groth16Verifier

```

## Key Learnings

### Why V2 Failed
1. **UltraHonk verifiers are too large for EVM** (60-100KB vs 24KB limit)
2. **bb.js ↔ Solidity format mismatches** (endianness, encoding issues)
3. **Version locking required** but fragile (bb.js vs verifier contract)

### Why V3 Succeeds
1. **Groth16 is EVM-optimized** (small verifier, fast verification)
2. **SnarkJS is standardized** (battle-tested Circom → Solidity pipeline)
3. **No format surprises** (exportSolidityCallData works perfectly)

### Critical Implementation Details
1. **Public signal order matters!** Circuit outputs come BEFORE public inputs
2. **Use MultiMux1 for Merkle trees** (avoid non-quadratic constraints)
3. **pathIndices convention:** 0 = left child, 1 = right child
4. **Always freeze artifacts** before testing (hash everything)
5. **Test CLI proofs first** before attempting browser/on-chain

- Always use `--skip-simulation` for real deployment

- Use full RPC URL, not aliases
