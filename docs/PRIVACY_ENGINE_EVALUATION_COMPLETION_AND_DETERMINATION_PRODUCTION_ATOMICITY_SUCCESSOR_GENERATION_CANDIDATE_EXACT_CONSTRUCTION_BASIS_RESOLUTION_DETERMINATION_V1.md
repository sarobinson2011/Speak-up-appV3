## 12. Exact Anchor Scheme

Every explicit candidate anchor is an ASCII lowercase token containing only `a` through `z`, `0` through `9`, and `-`.

Each anchor is emitted exactly once as `<a id="<anchor>"></a>` on its own line immediately before the identified heading or block, except a normative-row anchor, which is emitted at the beginning of the row's Identifier cell.

### 12.1 Artifact anchors

The artifact-root anchor is:

`pe-g2-art-<artifact-identifier-lowercase-with-each-maximal-nonalphanumeric-run-replaced-by-one-hyphen-and-leading-or-trailing-hyphens-removed>`

### 12.2 Numbered-heading anchors

Split a numbered heading label at each ASCII full stop. Encode every numeric component as exactly three decimal digits.

For a top-level heading, append the sentinel component `000`.

For a nested heading, append no sentinel.

The exact source prefix is:

`pe-g2-src-s<two-digit-slot>-sec-`

The exact specification prefix is:

`pe-g2-spec-sec-`

Examples:

- S25 Section 13: `pe-g2-src-s25-sec-013-000`;
- S27 Section 4.3: `pe-g2-src-s27-sec-004-003`;
- specification Section 27: `pe-g2-spec-sec-027-000`;
- specification Section 27.1: `pe-g2-spec-sec-027-001`;
- specification Section 31.3.1: `pe-g2-spec-sec-031-003-001`.

This variable-depth rule resolves every numbered source and specification heading without truncation or collision.

### 12.3 Changed source-obligation anchors

The exact grammar is:

`pe-g2-src-s<two-digit-slot>-clar-atomic-<three-digit-clause>-<two-digit-sentence>`

Each applicable clause sentence is declared once in the source artifact's successor semantic-obligation register. A section may refer to that declaration but must not redeclare its anchor.

### 12.4 SF, RF and normative anchors

SF family:

`pe-g2-spec-sf-<two-digit-family>`

RF family:

`pe-g2-spec-rf-<two-digit-family>`

Normative requirement:

the lowercase successor identifier, for example `PE-G2-EVAL-021` becomes `pe-g2-eval-021`.

### 12.5 Semantic-difference anchors

The exact anchors are:

1. `pe-g2-delta-atomic-001` — success boundary;
2. `pe-g2-delta-atomic-002` — exactly-one classification;
3. `pe-g2-delta-atomic-003` — forbidden completed-without-result state;

7. `pe-g2-delta-atomic-007` — non-retroactivity;
8. `pe-g2-delta-atomic-008` — implementation independence;
9. `pe-g2-delta-atomic-009` — privacy preservation;
10. `pe-g2-delta-atomic-010` — authority preservation.

### 12.6 Lineage and reverse-edge anchors

Predecessor lineage:

`pe-g2-lineage-<successor-requirement-anchor>-from-<predecessor-identifier-lowercase>`

Reverse trace:

`pe-g2-reverse-<sha256-of-complete-forward-record-tuple-fields-2-through-27>`

The reverse anchor uses the full 64-character lowercase hexadecimal SHA-256 and therefore does not depend on mutable edge ordinals.

### 12.7 Validation

Every declared anchor must equal its recomputed value and occur exactly once within its owning artifact.

Every trace destination must identify one inventory artifact and one declared anchor in that artifact.

Duplicate declarations, orphan anchors, dangling references, truncated heading paths and any actor-related anchor component block candidate creation.
