> exact complete formal-to-I164 relationship -> constructible

> exact components but missing identity, version, governance or realization relationship -> not constructible

## 9. Required Subject Distinctions

The published specification establishes the following distinct subjects and representations:

| Subject | Bounded role | Exact separation preserved here |
|---|---|---|
| Protocol Surface | Stable externally relied-upon capability boundary within one published generation | Surface identity is not a route, ABI item, deployment or implementation name |
| Protocol Operation | Bounded protocol-owned capability identified by one published Interface Contract | Capability is not execution and is not one Protocol Action occurrence |
| Protocol Action | One bounded public occurrence of protocol-defined behavior presented for Evaluation | Action occurrence is not operation capability, request, transaction or actor |
| Protocol Action Determination | Identified authoritative result of one completed Evaluation | Determination is not Published Result, response, transaction, event or state change |
| Published Result | Interface-level semantic outcome produced by realizing one governing Interface Contract and Protocol Operation | Result meaning is not its concrete or application representation |
| Application Response | Application-owned representation translated from a concrete interface representation | Response is not automatically a Published Result or protocol authority |

The relationship chain is:

> Protocol Surface contains or exposes Protocol Operation capability.
>
> Protocol Operation capability classifies but is distinct from Protocol Action occurrence.
>
> Completed Evaluation produces Protocol Action Determination.
>
> Realization of the governing Interface Contract and Protocol Operation produces Published Result meaning.
>
> Concrete specifications represent that result; adapters translate it; application responses expose application-owned representation.

No identity may be substituted across these subjects.

## 10. Candidate-Inventory Semantics

Candidate identifiers in this record are analysis-local coordinates only. They are not Protocol Surface identities, Protocol Operation identities, Published Result identities, protocol subjects, versions, actor identities or evidence-path states.

The inventory groups every materially relevant A03 candidate already identified by the accepted I164 evidence inventory and Engineering[186]-accepted Engineering[185] mapping evidence. Grouping does not merge the underlying tracked identities.

Version classifications mean:

- `none`: no version-like evidence;
- `label-only`: a title, path, comment, mode or local constant resembles a version but has no established A03 authority;
- `internal-schema`: an implementation-owned representation contains a local version field;
- `artifact-only`: a generated or cryptographic artifact identity exists without A03 identity authority.

Binding classifications mean:

- `none`: no deployment or runtime binding;
- `configuration`: address, chain or environment configuration only;
- `deployment-candidate`: bounded deployment evidence without A03 assignment;
- `runtime-candidate`: bounded observation without A03 assignment;
- `test-only`: reproducible component evidence only.
