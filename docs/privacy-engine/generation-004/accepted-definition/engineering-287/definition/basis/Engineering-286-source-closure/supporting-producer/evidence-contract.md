# External evidence assembly and exact boundary

The tables define documentary records inside the existing ReadObject evidence and authority endpoint, not new protocol subjects or expression fields. A source may validate a semantic record only under an independently adequate source-owned interpretation and competence basis. Structured evidence is not self-authenticating. Work IDs are documentary labels and never occur as a new PE-TSE host-call primitive.

For this proposed evidence carrier, serialize records in the order of the record directory (evidence-fields.tsv); each present record is L64(ASCII record name), U64(number of instances), followed by each instance as L64(concatenated fields). Each field is L64(ASCII field name) followed by L64(exact owning canonical bytes), in field_order. Record/field names are fixed directory literals. U64/L64 use unsigned big-endian 64-bit lengths, reject overflow/truncation/extra data. Empty bytes are a value only where their owning domain allows them; absence is encoded as zero instances for an inapplicable record, never an invented FALSE/zero fact. The applicable record set is determined by field-producer-joins-118.tsv and the phase. A required unavailable record prevents successful source validation. This proposed framing has no protocol authority before its owning source is admitted.

Scalar/ID/tuple semantic values use the retained exact TSEV1 type of the corresponding declared field. The directory's PI order is n,a,r. slot groups have 16 values in newest-first slot order, with each element L64(complete TSEV1 value); no sorting/deduplication. Call records are in execution order with complete raw calldata/return bytes and semantic callee/control binding. Existing owning-schema records retain their exact canonical bytes: no altered authorization preimage, attempt schema, transcript, groups/nodes/values/edges, or recovery table. Source-specific chain authentication/transition witnesses are exact external witness bytes plus their source-owned format/code/interpretation reference; their actual format and competence are unavailable realization inputs, not an invented proof parser. Admission must bind that exact interpretation before any witness is usable.

No free-form extra-field bag or whole-storage snapshot is permitted. Additional actual operations or source-specific witness subfields must be enumerated and included in a revised immutable declaration/evidence directory before admission. This is a closed design for the selected abstract authority-domain mechanism; it is not a claim of a closed concrete chain witness format. Repeated references do not collapse READ occurrences. To avoid a digest-only dependency, each consumed field's evidence includes the complete relevant records and their source validation binding; shared evidence may be physically deduplicated only if exact bytes are reconstructed for each read and each occurrence remains separate.

The 94 semantic root reads and 24 component reads remain explicit. When the pure E consumes a source fact, S70 records that read's exact canonical value plus an AUTHENTICATION node containing all its evidence bytes and an AUTHORITY node containing endpoint bytes. Therefore changes in contributing source evidence are represented, not hidden behind v/b/proof-result. Pure operation/call/control dependencies use the unchanged constructor. This does not import the external verifier's call graph as PE-TSE operations. The external qualifier must establish every listed call and evidence subfield under its own admitted source contract. If a realization performs additional work inside E instead of this proposed source-input boundary, this candidate does not cover it: it must expand the admitted program legitimately; it cannot inject a host-call or merely rename that work external.

Every source authentication path and external observer participates in the privacy model even though its source work is outside the pure expression execution. Source privacy and computation correspondence remain independent admission obligations. Phase failures are not serialized as completed negative inputs: see dependencies.tsv and design.md. A diagnostic prefix of failed verifier evidence is not a successful E package or a fresh recovery graph.
