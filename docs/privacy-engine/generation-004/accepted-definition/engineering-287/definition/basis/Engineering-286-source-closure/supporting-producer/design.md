# Concrete documentary producer design

This is one proposed mechanism, not a deployed producer or a new protocol primitive. The selected realization has a source-governed serialized authority domain containing two logically distinct scopes: membership introductions and scoped used state. On-chain verification remains authoritative. A qualified V result is an immutable input fact at the S70 read boundary; the pure PE-TSE program performs no host call. External evidence processing is separately specified below. No chain, signer, contract address, provider, appointment or actual occurrence is selected here.

## Admission

The admission boundary receives exact candidate proof representation and n,a,r. It decodes the three canonical UINT values without normalization and checks each against p=21888242871839275222246405745257275088548364400416034343698204186575808495617. Noncanonical bytes, out-of-domain values and inability yield no A/E/D. The transport route has two distinct commands internally: request new authoritative admission, or retrieve an existing occurrence result using its bounded reference. Arrival/retry is never the new-admission command by inference. A retried request with uncertain execution first reconciles the authoritative admission record; if its identity cannot be established it does not invent another admission. A deliberately new authoritative admission instantiates a distinct A even for equal proof/PI.

The proposed admission log uses a source-owned unique occurrence reference reserved atomically and never recycled, independent of proof/nullifier/actor values. Its concrete namespace is a realization input, not allocated here. The record binds candidate bytes, completed domain assessment, source authority, new-versus-retrieval decision and A. E identity is fixed only when complete source-derived R and coherent C are established; there is no E while that basis is unavailable. E/D completion is not a database receipt. Later retrieval uses the same completed D; it cannot redo E. Admission transport identifiers are private implementation evidence and cannot become protocol action identifiers or public correlation handles.

## History producer

The authority-domain transition rule maintains an append-only logical sequence H of valid introductions, each with a source-owned unique introduction identity, canonical scalar value and consecutive logical position. It increments h once for each valid introduction, including a newly introduced equal value. Re-observation/retransmission does not append. A genesis/initial root is absent unless an explicit valid introduction exists. The proposed realization stores the count and newest sixteen entries as a materialized suffix maintained by the same introduction transition; older history may be retained by its authority for validation but no whole-storage snapshot is read by E.

At a requested boundary the source reads h and that suffix within one authoritative state view. It validates the introduction transition/counter invariant from an independently admitted genesis/checkpoint and authenticated transition evidence, not by trusting the provider's list. It produces the exact 16 values/flags/identities/positions: occupied entries at h,h-1,...; every absent entry has value/position zero, empty identity and FALSE occupancy. Occupied values are scalars. It computes v by the retained 33-argument expression against the fixed r. A provider's inability to prove completeness is source inability, never v=FALSE. Empty *established complete* history gives v=FALSE.

The external evidence record binds authority-domain identity, membership scope, policy source bytes, phase and cut, authenticated count/suffix, validity/completeness path and fixed r. A checkpoint without independently established completeness is insufficient. The cut has no inherent height/finality meaning. Currentness at a gate follows the domain's authoritative read boundary, not lexical cut order or an RPC timestamp.

## State producer

The proposed state domain is a complete governed map over canonical (a,n) keys; it uses an explicit source-defined total-map interpretation, FALSE initially unless a valid scoped consumption has set TRUE. A membership/nonmembership proof is interpreted only under that total-map rule and its authenticated domain root. This is a proposed realization rule, not an assertion that missing I164 storage already has that authority. An unresolved lookup, wrong scope, unavailable completeness proof or unknown initialization is not FALSE. The consumer binds a,n,used,scope,cut and phase in the retained STATE-BINDING; only complete FALSE/TRUE may be used.

No reset, delete-to-unused or second TRUE write satisfies the chosen effect. A new A does not establish a new uniqueness scope. Authority authenticates the exact key and source state; product existence or wallet checks do not join R.

## Joint observation and phase evidence

For this proposed realization, membership and uniqueness scopes share a governing serialization domain but remain separately identified. The boundary captures both facts in a single domain state view. Evidence includes the domain-to-scope association, the state-view witness, each source's validity/completeness evidence and the requested phase bindings. This selected realization can use one state-view witness without imposing equal cut IDs or simultaneous retrieval as a universal protocol rule. Each own-source cut is mapped to that view by competent evidence.

For E the facts apply to fixed E/C and PI. For each gate they bind authorization/D/Q0/mapping/profile and digests, U, exact stage and comparison-attempt ordinal. A repeated payload does not prove phase applicability. The normal proposal reacquires observations for each gate. Reuse is allowed only with complete authoritative no-relevant-change evidence connecting the fact to the requested view. Neither equal cut labels nor two signatures is joint-currentness proof.

Separate basis validity from predicate availability. The phase witness authenticates the source associations and applicability of whichever predicate fact is available; it does not require both predicate values to be resolved to establish that basis. If v=FALSE is independently authenticated at the phase, missing unrelated b does not turn the entire joint basis invalid. Conversely, an invalid phase/scope/authentication basis takes precedence over MC. E still requires every assigned result complete before D.

## Verification and carrier

Use the completion-preserving qualification in verifier-qualification.md. A competent on-chain source may provide exact qualified verification facts and evidence; a carrier merely translates them. For this documentary proposal the preferred realization distinguishes arithmetic completion inside the authoritative verifier path and provides independently verifiable exact correspondence. This is a proposed future realization, not a change to I164. The archive Boolean is never consumed alone. The producer's external work is enumerated in dependencies.tsv and evidence-fields.tsv, rather than hidden in a caller-set completion flag.

For every one of the 94 ordered root values, the carrier requires one exact TSEV1 value of the declared type and the existing ReadObject object/source/anchor/evidence/endpoint metadata. It rejects omissions, extras, duplicates, reordering, trailing bytes, source/type mismatches and failed competence or assertion binding. Evidence is structured by the record directory in evidence-contract.md and is fully retained, not digest-only. The same source validation establishes ReadObject status flags. No caller-provided flag is trusted. The retained pure program remains the exact 17-type/53-definition/86-operation candidate, with 94 root fields plus 24 component fields. The added source evidence is joined per field in field-producer-joins-118.tsv; it is not a fifth primitive or a recursive host-call opcode.

## Component producer

For each component and side separately, supply source-established AUTHORITATIVE, AVAILABLE, VALID and AUTHENTICATED status facts; exact represented BOOL3 bytes; and independently authenticated canonical VALUE. Decode/canonicalize/normalize uses retained identity functions only after the required source validation. A status function cannot establish its own truth. Authorized ROOT-ELIGIBLE/SCOPED-USED values are TRUE/FALSE under the exact authorization basis; CURRENT is independently established at each gate. No current value is copied from Q0. Every actual repeated status/value READ retains a distinct occurrence and evidence binding.

## Comparison and indivisible effect

PRE-EXECUTION validates the complete baseline identity/profile/authorization/opening/state basis, then the original comparison algorithm; only equivalent permits execution. Execution prepares a scoped intent, not a write or D change. PRE-COMMITMENT enters the authority domain's serialized critical section. There it validates the exact current basis, observes current root eligibility and used state, applies the original comparison rows including both-true/incomplete-coverage guards, and commits only when equivalent. The successful transition changes exactly the selected (a,n) from FALSE to TRUE and records the outcome of this U within the same semantic boundary.

The source must exclude all authoritative state changes between final comparison and the decision/write, including root introductions, competing consumption and authority/context changes. A key-only lock or compare-and-swap on used is insufficient because r may expire concurrently. The proposed realization uses one domain serialization boundary for every contributing authority-state mutation; runtime correspondence must prove that all mutation paths participate. Product effects, unrelated keys and membership history are outside the successful write set and are preserved relative to the immediate pre-commit state, not restored from Q0. Two concurrently eligible Us on one key cannot both commit: after the first serialized commit the second observes used=TRUE and cannot pass.

A completed final conflict/indeterminate produces the exact immutable comparison classification/code and terminal U disposition. Loss of the required critical-section guarantee permits no claimed commit. Execution or revalidation failure follows the existing 21-row function; a failed U is never retried internally as the same U. A delivery timeout after a successful semantic commit requires reconciliation with the authoritative outcome, not a new write, restoration or invented failure. A known completed D likewise survives later delivery loss.

## Custody and mechanism alternatives

Admission/evaluator, membership/history, uniqueness, on-chain verification, evidence translation, joint assessment, comparison/commit, recovery and independent privacy assessment are role labels only. They do not create actor identities or appointments. Exact authorized access and potential transport/log/cache/diagnostic observers are enumerated in privacy/. Internal evidence is retained confidentially; public PI and the existing U/classification surface remain separately governed. A real public chain may expose additional calldata/state/call timing, which the model conservatively includes as possible disclosures rather than calling private by fiat.

A co-resident serialized authority domain is recommended for the concrete proposal because it can witness joint applicability and the no-intervening-change frame without inventing a cross-source ordering policy. A distributed alternative would require complete source-governed cross-domain snapshot and atomic-commit/currentness proofs. Neither is appointed here. For verifier qualification, a completion-preserving on-chain realization is recommended; retaining the Boolean verifier plus independently authenticated complete execution evidence is an alternative only if the exact evidence and competence suffice. Choosing a deployed platform or admitting either mechanism is outside this documentary authorization, so no repeated policy ballot is needed.
