# Exact verification qualification

The binding is (V,Z,proof bytes/encoding,ordered PI=(n,a,r),relation source+digest+anchor,artifact set+exact material,context,qualified result). Scalars are assessed before admission. Proof-point encoding and group semantics are governed by the exact relation/artifacts; the PI scalar modulus is not a license to reduce proof coordinates. Required malformed-point/computation cases cannot be classified negative unless the exact governing semantics establish a completed negative. Otherwise qualification is unavailable.

The selected archive call path is a diagnostic basis, not an adopted implementation. It reads the embedded scalar/base moduli and verifier key constants, checks three field values, initializes the accumulator to IC0, executes three multiplication/addition pairs, constructs a four-pair pairing input, calls pairing and returns a word. proof-calls.tsv enumerates every required call with exact operand relationships and return-length/completion requirements. For each actual call retain ordinal, callee semantic identity, exact input bytes, raw call success/return bytes and length, validated semantic result and its preceding control dependency. Include outer-call calldata, code/runtime/execution-environment identity, gas/exception/control evidence and authenticated on-chain execution binding. Raw call success alone is insufficient if environment/code/return shape is not established.

Qualified TRUE requires all three field/domain bindings, every required mul/add and pairing computation complete, exact input/key/relation/circuit correspondence, and pairing word exactly one. Qualified FALSE requires the same completion/correspondence basis with pairing word exactly zero. A failed or unestablished call, missing/short/noncanonical return, missing execution binding, wrong code/environment, artifact conflict, incoherent input or outer-call inability is no usable completed verification fact. Do not manufacture FALSE. E that has begun without all assigned results completing produces no D. The three-way distinction remains at the existing source-result interface and does not introduce a first-class outcome subject or public trace.

Preferred proposed realization: a future source-governed on-chain verifier preserves call completion separately from the pairing predicate internally; its result assertion is authenticated through the competent execution source. It need not publish detailed trace material. An external qualifier validates the exact computation/call evidence and cannot appoint itself as the on-chain authority. Alternative: retain the archived Boolean code, but acquire competent independently authenticated execution evidence sufficient to distinguish every failure branch. A generic RPC trace or a renamed revert is insufficient. No source edit, installation or live execution occurs here.
