## Acquisition and ownership

The integrated collector requires an independently supplied `trusted.occurrence_source_ref`, acquired through existing exact SOURCE-REF/anchor/source/material joins and complete dependency traversal. Its payload contains exactly format, binding, types and assignments. Binding includes owner/source identity, exact model, final outer profile, selected evidence contract, phase, attempt and mapping digests. Types are an ordered acyclic TSE declaration directory. Each assignment binds token ID, field class, original context, owning record, codec, type and value reference. Every required token occurs exactly once; missing, duplicate, conflicting, unknown or caller-substituted references reject.

Each value reference independently acquires an exact source-owned `CP4L-OWNING-VALUE-1` payload. It repeats exact binding, token, codec and type and carries canonical lowercase `encoded_hex`. The decoded **complete owning representation**, not its hash, enters validation and equality. All value bytes are parsed/validated before returning an equality index. Known `SECURITY:SCHEMA.field` classes must use the S90 codec and the exact registered field type; `.$record` must use complete record validation. No identifier grammar is relaxed. Per-field nullability requiring a containing-record interpretation is not inferred from a standalone null; such a source requires its concrete owning-record projection adapter rather than default acceptance.

The file-backed integrated entry point works for E, PRE-EXECUTION and PRE-COMMITMENT. The legacy hex-only `admission_kernel` occurrence conversion was unchecked and is now fail-closed: it reports INCOMPLETE-EVIDENCE-UNIVERSE and requires the owning adapter. Legacy static regression helpers remain. An absent/unavailable owning value cannot invoke the static predicate.

## Canonical bytes and exact equality

`occurrence_values/codec.py` validates TSEV1 headers, U32/U64 lengths, exact embedded type, kind, primitive spelling, nested type/arity and canonical strict unsigned-byte SET ordering. Large BYTES bodies are not materialized. Tuple/SET children are byte slices; adjacent SET elements are compared incrementally. The S90 path uses the existing canonical disk JSON parser and primitive/full-record validators; a JSON value with missing LF, alternative spelling, wrong domain or malformed framing is rejected rather than normalized.

`occurrence_values/index.py` keeps groups and token assignments in SQLite with 256 KiB cache and disk temporary storage. SHA-256 and length narrow candidate representatives; complete byte comparison decides equality. Unequal values sharing an index bucket remain separate even under forced bucket collisions. Canonical source digests and token SHA-256 remain real hashes when the test forces the *index bucket* function to collide. No grouped value replaces its distinct token occurrence.

Group IDs are deterministic in required token order. Model-sized group counts establish exact equality pair cardinality without enumerating pairs. Closure unions a spanning star in each exact group plus all established structural edges. Native scoped descriptors preserve original index ordering and map every actual token to a fixed exact group. Thus the unchanged native membership engine admits an occurrence equality iff the two validated owning byte strings are equal. Static descriptor generation is unchanged. Structural and potential sets retain separate membership/uniqueness/cardinality obligations. Whole-file SHA-256 is still computed from consumed serialized input bytes at validated EOF, never from descriptors or concatenated segment hashes.

## Recovery and resources

Acquisition uses 4K's exact source snapshots and canonical disk indexes. A complete equality index and representative byte files commit with fsync/atomic replacement and an authenticated stage receipt binding exact source directory and source/model/profile/contract/phase/code identities. Corrupt or incompatible indexes/receipts reject. The terminal collector pins this stage among its prerequisites. Partial equality construction is discarded and rebuilt: orphan files or an uncommitted SQLite database are not evidence of completion.

Before completed equality-index reuse, all current owning sources/dependencies are reacquired and canonically validated; saved representative files and the database are rehashed. This costs linear source/decoded-value reads even though grouping/comparison computation can be reused. Within one invocation, cached exact hashes rely on 4K's explicit trusted-executor and quiescent-input boundary. Permissions, timestamps, locks and key/journal possession are not byte identity or source qualification. Native link resumes rehash consumed prefixes; pure Ed25519 rebuilds its consumed original-message prefix. No constant-time recovery claim is made.

Memory is bounded by the required model/identity/type/group indexes, open SQLite documents, 64 KiB streaming chunks and explicit scalar/depth caps. TSE type names/ID/UINT scalars are capped at 1 MiB, type declarations at 4096 and nesting at 128; BYTES length does not impose aggregate RAM growth. Existing JSON scalar/canonical parsing caps remain. SQLite stores references, complete representative files store bytes, and source hex decoding can require additional transient files. Worst case, many equal-sized values in one digest bucket cause quadratic exact comparisons; memory stays bounded and no incorrect equality is accepted. Interruption can replay all unfinished acquisition/index work. Budget those costs explicitly.

A demonstrated **remaining code gap** affects full retained-model scale: request occurrence bindings and source file metadata are still inline in the 16 MiB carrier; durable scheduler catalogs still have 1 MiB receipt limits. Even an unrealistically minimal 426,984-token reference directory exceeds 91 MB. The adapters are executable and complete for the declared bounded source language **within these caps**; this is not full first-kernel code completeness for the retained finite contract. See `results/4L-catalog-capability-gap.json` and the updated completion checklist. No cap was silently raised and no universe reduced.

The projection boundary has a reproducible bounded witness: `python run_4l_capability.py`. `results/4L-projection-boundary.json` shows that the retained complete ASSESSOR-EVENT schema accepts input_bytes=null in the tested READ record, while the direct ordinary BYTES codec rejects standalone null. Correct support requires extracting/validating the field against the exact owning record and its identity/applicability, not weakening primitive BYTES. No source qualification is asserted by this local schema experiment.
