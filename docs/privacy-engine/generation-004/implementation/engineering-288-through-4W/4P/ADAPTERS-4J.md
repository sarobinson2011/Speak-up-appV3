# Executable acquisition and compatibility

`integrated_auth.collector.run` is the supported file-backed integration entry point. Carrier version CP4J-FILE-COLLECTOR-1 deliberately rejects old journal/carrier reuse. Its signature/object wire formats are unchanged. The `semantic_stream.storage` module supplies exact byte slices, streamed hex, canonical JSON validation and disk-indexed objects/arrays. `semantic_stream.provider.StreamingProvider` selects the same two inherited source-specific invocation codecs and concrete finite assessment law.

The outer profile is copied from exact consumed bytes and checked against its expected identity; immutable member lengths/order/domain are decoded into byte slices. PRIVACY is parsed canonically into indexed nodes. Immutable security and external records still pass the existing schema, availability, primitive, cross-record, ownership and complete coverage checks. Small nodes are ordinary Python objects; large containers expose lazy dictionary/list interfaces to those checks. Internal container type checks recognize those interfaces; no accepted ID, FIELD-CLASS-REF, OBLIGATION or record field is broadened.

Every material/source reference retains owner/source/anchor/material correspondence against independently supplied conditional source facts. Entire declared dependency closures are traversed; absent transitive dependencies fail. Static construction still rejects final-profile/result dependencies and cycles. The exact same argument, complete security object, model digest, consumed source/material bytes and premise directory enter each invocation. NAMED-L64-V1 uses the original names and U64-BE lengths. CANONICAL-JSON-V1 retains the original nested hex and canonical JSON+LF representation. Output is a private file with its exact SHA-256, not a descriptor digest. Independently authored in-memory oracle preimages match both codecs byte-for-byte.

CALL/RETURN and complete source-owned traces are compared to exact invocation/result bytes. Certificates are compared with complete source-owned worlds, not with issuer PASS flags. SQLite indexes check duplicate finite outcomes, positive normalized full support, collision counts and exact statistical distance; fractions remain exact. All policy, authority, qualification, non-vacuity, scope, whole-view decomposition, multiplicity and budget prerequisites remain in the ordered collector. Successful cryptography cannot supply missing competence.

## Memory and capability bounds

* Input/read/hex blocks: 64 KiB. The caller's supplied-link chunk option remains independently bounded at 1 MiB.
* Canonical JSON small-node decoding: at most 64 KiB serialized bytes. Ordinary strings/object keys: at most 1 MiB of encoded content; nesting: 128 containers; integer lexical conversion: 4096 bytes. Larger unescaped lowercase even hex strings are streamed. Large other strings are an unsupported capability, not an amended protocol rule.
* No whole profile, security directory, source trace, artifact certificate or invocation must fit in memory. There is no aggregate semantic-object size ceiling. Individual records may span large containers/hex values; each ordinary scalar and parser nesting buffer remains bounded as above.
* SQLite JSON cache: at most 256 KiB **per acquired/indexed document**, plus connection/node/offset metadata. The complete source identity/directory and record-reference indexes remain proportional to required input identities; this is not a claim of fixed RAM independent of model/index size. Tiny documents up to 64 KiB can remain decoded in the per-input cache. Repeated source acquisition within one call reuses its privately copied bytes.
* Model/token/structural/ledger/reference/closure indexes remain Python indexes proportional to the required complete model and duty/record identities. This checkpoint does not make the full model index constant-space. Large payload/trace length does not multiply those indexes.
* Finite distribution SQLite caches: 256 KiB; one bounded outcome value is handled at a time. Outcomes longer than the ordinary scalar capability, unsupported source mechanisms and exact arithmetic beyond a 1,048,576-bit denominator budget fail with INCOMPLETE-EVIDENCE-UNIVERSE. No approximate probability or sampled outcome is substituted.
* Transport manifest remains a bounded 16 MiB metadata object. The prior 64 MiB trusted-contract materialization is removed on this path. Signature lines/evidence rows retain the previous explicit small-table guards.
* Legacy standalone `admission_kernel`/CP4E hex-carrier helpers remain for bounded regression compatibility. They retain their documented materialization guards and are not the scalable integrated entry point. Fixture construction/signing is deliberately separate and still materializes bounded synthetic data.
* Large non-static occurrence typed-value storage and exact equality grouping are not generalized by 4J: the inherited occurrence path requires complete in-memory byte values. A larger occurrence source needing file-backed values remains an explicit implementation task; it must fail closed, not silently use symbolic static values.

Disk stores exact acquired inputs, JSON offset/type/child indexes, decoded certificate bytes, each exact invocation part and invocation preimage, and finite distribution indexes. Storage grows with bytes actually required by the exact source codec and semantic node count. SQLite row/child overhead depends strongly on record density. The measured larger case used about 204 MB of temporary files at completion, in addition to about 161 MB of supplied fixture files. That is an end-state measurement, not a proven peak bound. Reserve at least 1 GiB scratch for its validation and 2 GiB RAM/5 GiB scratch to regenerate it conservatively. Full-scale estimates require real authoritative objects and separately sized model/index data.

## Recovery and authentication

Acquisition records consumed byte offset, exact SHA-256 prefix identity and completion in the inherited HMAC-protected, atomic collector journal. It binds carrier and independently supplied trusted-contract exact bytes/paths, active schema, Python implementation identities (including both new modules), backend/key/signature and exact model/contract/source/profile/bundle identities. Every resume reacquires and hashes each consumed source prefix; size and timestamps alone never establish identity. File mutation during acquisition fails its complete identity check.

JSON indexes and partial invocation files are disposable. Each resumed attempt builds fresh indexes/parser state from the verified bytes; it never imports a saved semantic PASS, SQLite cache or caller-provided parser state. Mid-token/container interruption therefore costs another acquisition/index pass, but cannot authenticate partial input. Byte acquisition can advance by --new-bytes before parsing. Completed acquisition stages still reread their bytes on later invocations. Scalar/order/availability/dependency/trace/result checks rerun.

The existing pure Ed25519 backend still consumes the original V2 signed message, and still reconstructs its state by full-prefix replay. No digest-signature or Ed25519ph substitution occurs. Read-ahead, separate structural/potential completeness and exact consumed stream SHA remain governed by the retained validator. SHA-256 is never composed from segment digests.

Atomic journal writes preserve the previous or next valid commit; interrupted temporary writes are ignored. Interrupted semantic stores are removed on normal exception/signal cleanup; an uncatchable process kill can leave an orphan temporary directory, which is not a receipt and is never reused. It can be deleted after verifying its process is no longer active. The receipt retains enough exact binding/prefix evidence to reconstruct from original inputs. Recovery remains unsuitable for the complete multi-terabyte run until the replay costs are addressed.

PAUSED has no positive binding/authentication conclusion. Independently discoverable failures are collected in the existing ORDER; the unread suffix can still contain an earlier failure. Final completion recomputes the full result. Missing qualification suppresses dispositions/budgets even when all byte and signature checks succeed. No actual source or mechanism qualification is established.
