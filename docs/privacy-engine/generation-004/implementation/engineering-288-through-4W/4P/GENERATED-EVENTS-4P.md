# Source-grounded generated events — checkpoint 4P

4P completes the ten `CP2-RECORD-PARSER` and three `CP2-REFERENCE-MATERIAL`
containing-event adapters. It also fixes a demonstrated disk-backed ledger-copy
failure. Actual admission remains disabled. The active 4I amendment, accepted
sources, selected contract/model serialization, equality predicate, primitive
codecs, pure Ed25519 backend and failure ORDER are unchanged.

## Source basis and exact selectors

`rebinding/selected-contract.json` specifies parser.event_fields, branch_domain,
record_parser_attempts=2, material_acquisition.fields/status_domain and
reference_list_elements=2. The exact retained implementation of those selected
laws is `provenance/4O-retained-cp2/catalog.py` (PARSER_FIELDS, MATERIAL_FIELDS,
Catalog._build) and `expand.py` (record_keys, lines 59–71). S90 correction section
2, lines 400–423, requires exact containing bytes and canonical typed-value
hashes; section 3, beginning line 426, requires complete field/event/parser and
actual guarded occurrence coverage. No source definition or identifier law is
changed by this acquisition adapter.

Parser occurrence keys are `SCHEMA:record:PARSE:000001` and `...:000002`.
Material occurrence keys are `SCHEMA:record:REF:field:000001`, and item 000002
only for a declared LIST-SOURCE-REF. Context is an independent exact dimension.
Record IDs come from the required bound model and the source-owned containing
object. They are not inferred from an untrusted carrier or renamed.

## Conditional acquisition grammar

CP4P-GENERATED-RULES-1 pins the selected contract, active amendment, S90 grammar,
actual parser implementation and adapter. It is acquired through an independent
source reference in the laboratory contract. CP4P-GENERATED-DIRECTORY-1 gives an
ordered complete directory of exact source-owned event references. Each
CP4P-GENERATED-EVENTS-1 document contains the source/model/profile/contract/phase/
attempt/mapping binding, context, kind, schema, parent record/invocation,
containing object and rule references, and the complete two parser attempts or
single reference acquisition. CP4P-GENERATED-PROJECTION-1 is only a locator into
that already validated containing event. It cannot supply replacement values.

These versioned source-owned carrier languages make the finite conditional
acquisition law executable. They are not new V4 normative fields, a production
observer appointment, or a universal parser. The selected contract lists the
thirteen generated fields but does not supply a universal concrete event
transport; the laboratory source explicitly selects this transport and its
field types. Input/output record fields carry the exact canonical encoding of
the typed owning record as S90 BYTES (canonical lowercase JSON hex plus LF).
Schema/record/parent IDs use ID; ordinals use UINT; owner/grammar/material refs
use SOURCE-REF. Phase uses the existing stage domain, and two local enum type
names denote exactly the retained branch/status domains. Those names are never
installed as new primitive codecs. Null BYTES is admitted only through the
validated containing-event outcome. Standalone BYTES null still rejects.

Directory completeness is not a count-only assertion. Required keys and all
field/attempt masks are derived from every generated token in the exact model.
Each supplied entry must be legal, strictly ordered and unique; its complete
mask must match the ten fields times two attempts or three material fields.
Legal membership, uniqueness and equal cardinality then prove equality with the
required directory. Every token is acquired before equality/scoped validation.
An absent, extra, duplicate or conflicting event cannot be hidden by a count.

| Outcome | Required validation |
|---|---|
| VALID-LOCAL | Run the retained canonical/local S90 validator; exact record ID; input equals the full record in the authenticated containing object; output is exactly the canonical returned-record bytes |
| INVALID-LOCAL | Rerun local validation and observe a real schema/encoding rejection; no output bytes. Resource/capability failure or interruption cannot establish this branch |
| UNAVAILABLE | No input/output bytes; exact source-owned guard binds context, record, parent invocation, phase and attempt |
| INAPPLICABLE | Same exact guard correspondence, explicitly no invocation; no fabricated input/output |
| PRESENT material | Match the complete actual consumed lookup bytes, reference digest and source/anchor; validate the declared CP3 material envelope and complete dependency closure |
| UNAVAILABLE material | Actual material lookup is absent in the captured source directory; exact_bytes is null; the non-null owning reference still joins the complete containing record |
| INVALID material | Actual acquired bytes match the recorded bytes but fail digest/envelope validation; no unsupported semantic grammar is silently treated as valid |

An absent parser input does not erase its required event fields. If its underlying
record is absent, only justified no-input outcomes can project; VALID-LOCAL still
requires the exact available containing record. Conversely null SOURCE-REF,
absent list item or unavailable containing record cannot manufacture a material
acquisition child. Such a required occurrence fails completeness. A source must
supply the independently qualified actual guard directory; 4P does not shrink
the retained symbolic universe to force a pass.

## Integration and bounded lifetime

`occurrence_values.acquire` invokes Generated.prepare before equality indexing,
then dispatches generated carriers separately from S90 projections and ordinary
owning values. Direct carriers cannot bypass either containing grammar. The
result uses the unchanged exact, collision-safe byte equality index, scoped
closure, structural/potential link validator, pure Ed25519 authentication and
ordered ledger collector. Current code identities are pinned in both independent
fixture source assertions and scheduler receipts. Collector/scheduler versions
are CP4P; earlier journals are incompatible.

The required-event directory, acquired references and checked identities use
three disk maps with 256 KiB SQLite caches. Event arrays have exactly two or one
entries. Large bytes remain file-backed hex/byte ranges. The retained 4N index
pool, eviction guards, bounded caches and cleanup remain unchanged. Every field
access reacquires and validates its entire event and dependent inputs; checked
identity metadata only tracks correspondence/counts and cannot suppress these
checks. This deliberately retains reread costs instead of trusting stale caches.

Ledger construction previously deepcopy'ed lazy source arrays, raising
`TypeError: cannot pickle 'sqlite3.Connection' object` on this complete fixture.
`ledger_kernel.construct.from_source` now uses the immutable acquired snapshot
with read-only validators. No source bytes, classifications or validation rules
are dropped. The previous code/hash, initial failure result and unit reproduction
are retained under provenance/4P-before-ledger-fix and results/4P-smoke.json.

Recovery retains exact input/implementation/backend/prerequisite bindings.
Incomplete generated validation/equality is rebuilt; completed acquisition and
JSON indexes are reused only after exact checks. Native link resume and pure
Ed25519 prefix reconstruction are unchanged. A terminal receipt still requires
all exact input/artifact identities. Source metadata, directory membership,
signatures, guards and journals never establish competent external qualification.
