# Disk-backed catalog contract and implementation

This is a transport and execution-storage change, not a normative amendment. Active 4I FIELD-CLASS-REF, selected contract, complete model, equality predicate, exact V2 preimages and canonical pure Ed25519 backend are unchanged. Historical 4L ZIP is retained exactly.

## Source grounding and complete membership

`accepted/sources/PE-G4-SOURCE-S90.md`, section 3 (static and actual occurrence universes) and token/link constructors (retained source lines 749–761), require the complete independently grounded actual occurrence universe and owning-source bytes. S90's canonical security-byte paragraph (lines 400–413) and retained `accepted/sources/retained/S70.md` canonical encoding clauses remain enforced by 4L codecs. No catalog hash is an owning value or a qualification. Existing SOURCE-REF owner/source/anchor/material joins, source-owned assignments and complete dependencies remain required.

A small carrier may replace `materials`, `source_objects`, and `request.occurrence_bindings` with `{"$cp4m_directory":{"path":...,"bytes":...,"sha256":...}}`. `trusted.occurrence_bindings` has the same option. For external source-file maps, independently acquired trusted input must contain `file_directories` with the exact corresponding descriptors. Directory paths remain contained beneath the input base. Inline small historical interfaces still work at their unchanged limits. Their presence is not required for large catalogs.

Directory bytes: ASCII canonical compact sorted-key JSON plus LF header, then strictly increasing unique-key `[key,value]` JSON+LF rows. Header fields are exactly `format=CP4M-CATALOG-1`, `kind`, `binding`, `count`. Binding includes source ID/digest, model digest, final profile digest, selected contract digest, phase, attempt and mapping digest. Each line is at most 65,536 bytes, keys at most 4,096 UTF-8 bytes; these are explicit implementation limits, not broadened normative laws. Noncanonical spelling, duplicate JSON keys, duplicate/conflicting directory keys, incorrect order, missing/trailing rows and bad framing reject. Exact consumed directory bytes are hashed; the expected full input is rehashed before resume and before publication. No timestamp-only identity check.

A source-file row maps an exact digest to its contained path/length/digest. An occurrence row maps an unchanged full required token ID to exact SOURCE-REF. The latter is compared to both the independently supplied trusted directory and the source-owned complete assignment payload. Assignment token, field class, context, owning record, codec/type and owning source/model/profile/contract/phase joins remain checked before any value is used. Required-model IDs are never inferred from caller rows. **Legal membership + unique keys + cardinality equal to the complete required finite set imply equality**; a count alone does not. 4L's separate structural/potential completeness and whole-file digests remain unchanged.

`DiskMap` uses SQLite with 256 KiB cache and disk temporary storage; map values are bounded JSON rows. Read-only views open/close their connection per operation/iterator. Source-owned assignments are joined in a disk map instead of a second resident reference dictionary. Receipt map copies use SQLite's snapshot API and require exact copied counts. Directory indexes are transport facts until the source-grounded collector establishes correspondence. Neither trusted laboratory fixtures nor execution MACs establish authoritative source qualification.

## Durable scheduler storage

Inputs, artifacts and prerequisites in stage receipts are replaced by exact SHA-256/count/name descriptors of immutable SQLite generations. The receipt MAC binds these descriptors plus job, code/backend identities, stage, completion and result. `read` rehashes referenced databases before use. Terminal reuse checks each exact input, every required completed prerequisite receipt, their artifacts, native journals and ledger output. Missing/stale/substituted/incomplete prerequisites cannot inherit a terminal result. Receipt metadata remains below the unchanged 1 MiB limit; carrier control bytes retain the unchanged 16 MiB limit.

Per-file parser replay progress now has individual versioned stage receipts rather than accumulating in the small main journal. Per-invocation input-check/receipt-discovery maps are disk backed too. Their contents are not independently authenticated source evidence. Ordered independent failures retain existing categories/precedence and suppress positive dispositions/budgets/readiness. Actual admission remains disabled.

## Recovery and input immutability boundary

Catalog checkpoints bind the exact directory descriptor, full header binding, job and implementation identity to an immutable SQLite generation, next byte offset, last key and count. Pauses occur at completed row boundaries. Resume rehashes the whole original directory and the saved DB, copies the committed generation, seeks to its offset and continues. No hash state is synthesized from segment hashes. A successful directory digest is always the SHA-256 of the exact whole input. Partial-row/transaction work lost to abrupt interruption is rebuilt; only an authenticated committed generation is reusable.

Generation data is committed/fsynced before an atomic MACed pointer update. Interrupted pointer writes leave the prior pointer valid; unpublished generations are harmless orphans. Corrupt/incompatible checkpoints reject rather than silently becoming completion. A controlled deadline publishes completed rows. Before initial publication an abrupt interruption restarts construction. Collection can be resumed through the main journal even if paused during initial directory construction.

Within a call, cached exact checks require trusted quiescent execution/input custody. Permissions, advisory locks, timestamps and journal possession alone are not byte identity. Cross-process locks serialize supported job entry points. Fresh invocations rehash inputs and artifacts. Native supplied-link validation still rereads its consumed prefix, and pure Ed25519 still reconstructs its original-message prefix; neither replay cost is claimed constant. No new crypto state export or signature variant.

## Storage and current boundary

The full metadata test consumes 252,775,296 canonical directory bytes covering all 426,984 retained tokens. Separate source-file and reference indexes are 124,936,192 and 173,780,992 bytes. Scheduler input/prerequisite maps also each cover 426,984 rows; final receipt is 9,761 bytes. Required token oracle is disk backed. Benchmark dataset construction does not produce actual owning values or executed prerequisite stages.

Incomplete catalog rebuild uses a temporary DB plus the retained committed generation; allow roughly twice the largest catalog DB during resume. Each resume rereads the complete directory and saved DB; complete reuse avoids parsing but not identity I/O. Immutable generations need offline reachability-based cleanup only after the job is closed; no automatic deletion is used here. Exact current test disk use is in results.

The catalog capacity blocker is resolved. A separate retained semantic-store lifecycle limitation is demonstrated: `semantic_stream/storage.py` keeps every `Document.db` open until `Store.close`. Under a 96-file limit, independent canonical-document acquisition failed after 92 documents. The catalog path does not retain read-only connections that way. A bounded semantic document/index/cache lifecycle is needed before complete actual-value acquisition at retained scale can be claimed. This is an implementation capacity boundary, not a new accepted-definition defect. Source-specific containing-record projections remain a separate adapter task.
