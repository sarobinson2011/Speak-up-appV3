# Practical recovery composition

## What is implemented

`python -m integrated_auth` now enters `recovery_schedule.runner`. The prior direct Python collector remains available for regression comparison. The active collector uses the same pinned canonical pure Ed25519 backend for every message size. No cryptographic preimage, normative grammar, qualified status, source/model identity or failure ordering is changed.

The stage sequence is dependency driven: exact semantic acquisition and canonical disk indexes; independently grounded source/authority/model/contract/closure joins; exact four-file object/outer acquisition and pure signature checks; source-grounded tokens and native supplied links; semantic assessor/ledger collection; terminal ordered result. Independent failures remain collected by the retained collector. A paused invocation has no complete assertion. A corrupt or incompatible recovery envelope is rejected before using its conclusions; it is not a newly completed semantic assessment.

`native.descriptor` accepts the collector's validated ScopedModel, not a manifest-supplied descriptor. It projects original token order to contiguous local indices, retains exact token names and structural relations, and maps fixed symbolic equality classes exactly. The proof binds the complete model digest, original index sequence, phase, required separate cardinalities and generated descriptor SHA-256. The companion contract binds scope/profile and the actual contract entry. Source-owned seed closure and cross-bundle joins are still established by the source adapter; the descriptor does not establish them.

The retained native worker enforces byte framing, identifiers/relations/orientation, lexical four-cell order, uniqueness and ordinal laws, exact legal membership and separate structural/potential completeness. For each required finite set S, legal membership establishes R subset S; strict uniqueness and |R|=|S| then establish R=S. Counts without those predicates do not establish equality. Structural and potential sets remain separate obligations. A partial/rejected stream has no complete-stream SHA-256. No descriptor hash is substituted for serialized rows.

## Durable state and trust boundary

A fresh invocation binds its exact manifest, trusted laboratory contract, code/schema/native/backend identities, input paths and expected byte hashes. Each bounded HMAC receipt binds stage inputs, outputs/artifacts, completion and prerequisites. The terminal ledger pins completed prerequisite receipt hashes and the exact main journal/output. Cached indexes are opened read-only only after their exact database and source-byte hashes are verified. Native receipts pin the native journal; resume also checks that journal's input/model/contract binding against the newly derived scope.

The execution key authenticates local computations only. The threat model requires a trusted executor/key/code and quiescent inputs and internal artifacts throughout one invocation. Concurrent hostile modification of files by another writer during a validated invocation is outside this boundary. The implementation does not enforce a cryptographically immutable storage system. Permissions, modification times, owner-only keys and advisory locks are operational safeguards, never byte-identity proofs or source qualification. Fresh invocations rehash the bytes they reuse. Within one invocation, successful exact hash checks and byte-range digests may be reused while the stated quiescence boundary holds. No cross-invocation metadata-only shortcut exists.

New files use file fsync, atomic rename and directory fsync. An interrupted write leaves either the prior valid receipt or the new valid receipt; orphan `.part` files are not completion evidence. Main/native/authentication journals, snapshots and index receipts commit separately. A completed substage can survive interruption before ledger commit. Do not edit a journal to repair it: retain it for diagnosis and start a new job when incompatible/corrupt. Absolute paths are part of bindings; moving a working job requires restarting its identity. The ZIP provides inputs/commands for fresh restoration, not portable authority to adopt old absolute-path receipts.

## Reuse and unavoidable replay

| Stage | Completed work reused | Recovery bytes/work still required |
|---|---|---|
| Semantic acquisition | Exact private snapshot | Source and snapshot full hashes on a fresh invocation; interrupted acquisition reconstructs its consumed prefix and spool |
| Canonical JSON/index | Complete disk parse index | Exact source/subrange digest and full DB hash; incomplete parse/index is discarded and rebuilt |
| Assessor/ledger | Terminal ordered result, if every prerequisite/input remains exact | Before terminal commit, assessor evaluation/semantic joins can run again using the retained indexes; no partial assessor execution state export |
| Four-file acquisition/object/outer | Completed exact object/outer computation | Exact constituent input hashes and stage-journal hash on reuse; partial acquisition retains its original prefix reconstruction behavior |
| Native supplied links | SHA-256 state, parser partial row, prior lexical tuple, ordinal and separate counts | Every native resume rehashes the consumed prefix and reloads its index before processing new bytes; no potential rows reconstructed or enumerated by descriptor construction |
| Pure Ed25519 | Completed signature-verification computation | Incomplete verification rereads and sends the entire consumed original-message prefix to rebuild backend SHA-512; no reviewed safe state export is available |
| Terminal ledger | Exact ordered failures/verdict and computed bindings | All original input identities, artifact hashes and complete prerequisite receipts rechecked; full bytes may be reread even when no semantic computation repeats |

Native read-ahead is handled by retained worker state: the durable offset counts consumed bytes, pending partial-row bytes and SHA state are persisted consistently, and unconsumed bytes are read again. The exact file descriptor used for prefix checks is retained for native continuation. A whole-file SHA-256 is returned only after validated EOF, expected input identity and separate completeness checks. Pure verification succeeds only on exact-message EOF and exact constituent bytes; partial processing never authenticates.

Let N be stage input bytes, p the saved prefix and q new bytes per invocation. A partial native resume costs p bytes of SHA-256 reread plus q bytes of parsing/hashing and an index reload. A crypto resume costs p+q original-message bytes plus backend SHA-512 processing, with full per-file identity checks upon completion. Repeated equal-size chunks can reread approximately N(N/q-1)/2 prefix bytes. A fresh terminal reuse requires O(total exact input + cached artifacts) I/O, not O(1). `identity_bytes_reread` counts scheduler full-file checks only; it excludes backend/native prefix replay, parser subrange hashing, normal source acquisition and other inherited passes. It is not total job I/O.

## Practical invocation schedule

1. Prepare exact source files and appointed authority/qualification evidence. Fix paths, implementation and input identities for the job. Establish operationally quiescent custody; if this cannot be guaranteed, do not trust within-invocation caching. Actual admission remains disabled.
2. Use one long-lived scheduler invocation with an estimated finite wall budget. Choose `--new-bytes` large enough to amortize native index/prefix rereads. `--quanta` allows multiple bounded steps inside that invocation, reducing repeated source/artifact hash checks; it does **not** remove native prefix rereads between native steps.
3. Set `--auth-new-bytes` to at least the largest exact signed message and allow its measured verification time. This can finish cryptography in one stage while native row validation remains resumable. For a later full run, budget hours if necessary from actual throughput; the old 60-second internal collector ceiling is removed. The current turn's benchmarks remained externally limited to 60 seconds. No full-run launch is authorized by this document.
4. Graceful byte-limit pauses commit state. SIGINT/SIGTERM or deadline interruption preserves last committed state; work after it can be lost. Resume with identical command identities and a larger adequate budget, not frequent tiny intervals. A deadline reached during prefix replay can make no forward progress; it does not license skipping that prefix.
5. Complete each scope's prerequisites and ledger. On subsequent fresh invocations, expect exact byte rereads even for a completed result. These computation receipts are never source authentication, authority appointments, assessor competence or qualification.

## Resource bounds and limitations

Parser buffers remain inherited bounded chunks/line/scalar limits (see ADAPTERS-4J.md). JSON disk cache is 256 KiB per open index; memory also depends on the required model/reference/receipt indexes and open documents. Manifest cap is 16 MiB. Local receipt/main-journal cap is 1 MiB; exceedingly many inputs/prerequisites can exhaust this capability and require a separately reviewed disk-backed scheduler catalog. No such job is claimed supported. Native scoped index supports 2–1,000,000 tokens and at most 10,000,000 structural rows with bounded identifier/kind cells. Events retain only the latest 1,024 in memory and stream progress to stderr.

Durable storage is exact completed semantic snapshots plus SQLite indexes plus scope descriptors, bounded journals and result files. Transient acquisition/index copies can briefly double the relevant working set. No native full link stream copy is stored. The complete retained index alone is 236,894,099 bytes on disk and measured 478.4 MiB native RSS; a live Python full-model object, snapshots, filesystem cache and other indexes are additional. A full-model end-to-end RSS or disk peak is not established by that isolated native measurement.

The native composed route currently covers STATIC-ADMISSION's accepted symbolic predicate. E/PRE-EXECUTION/PRE-COMMITMENT retain the prior bounded small-value path; scalable owning typed-value acquisition and grouping remain the next code task. Full-scale integration with authoritative sources, complete real ledger and actual streams is unperformed. Historical backend review is an implementation review, not competent external qualification.

## Pass-count planning and uncertainty

For an uninterrupted scope with a large links file L, the minimum dominant passes in this implementation are one native membership/order/count/SHA-256 pass, one exact object-acquisition/hash pass, and one original-message pure-signature pass. Source semantic/token parsing and model/contract verification add separate work. The final ledger commit hashes receipt artifacts, not a new full link pass. A subsequent terminal reuse rehashes exact original L once per distinct path/hash within that invocation, plus private semantic snapshots and index artifacts. Different files holding identical bytes are separate identities and may be read separately.

Partial four-file acquisition can reread its saved per-file prefixes and then reread object-member prefixes a second time to reconstruct the ordered V2 length-prefixed object hash. Native and pure-signature prefix rereads are additional, not shared with those passes. `--auth-new-bytes` avoids imposing a small native chunk budget on those authentication stages. Stopping during reconstruction can waste the entire attempted prefix replay without advancing a journal.

The retained 4G measurement verified a 100,664,676-byte exact synthetic message in about 0.95 s at 22,468 KiB controller RSS; separate signing used 218,804 KiB. It remains historical transport performance evidence, not a semantic full-stream witness. As an illustrative planning rate only, 100 MB/s gives about 17 minutes per 100 GB pure-message pass; real cold-storage/competing-I/O performance can be 2–10 times slower. Do not multiply the fast 4K small-fixture rate into a claimed full-universe runtime. Before a full run, size the actual signed files, semantic records and indexes, sum the passes above plus anticipated prefix replay, and allow restart headroom. Complete serialized supplied-link size and actual full-model source-ledger memory are not newly measured here. The separately retained binary potential-pair stream size is 729,259,627,770 bytes; this is not the supplied-link TSV size or a computed identity. None of those full bytes were read or generated in 4K.
