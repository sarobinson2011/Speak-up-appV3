## Carriers and acquisition

CP4L-OWNING-OCCURRENCES-1 remains the exact source-owned assignment directory. Every required token still has one unique assignment and independent source reference, with exact source/model/profile/contract/phase/attempt/mapping binding, surface, context and record identity. Neither cardinality alone nor caller metadata establishes membership.

The new conditional acquisition carrier CP4O-S90-PROJECTION-1 binds those same dimensions, S90-JSON-LF codec and registered type, an independently anchored containing-object reference and exact record selector. CP4O-S90-CONTAINER-1 carries the complete external PE-G4-SECURITY-RECORDS-V4 object as streamed hex, full binding and independent source-rule reference. Decoded bytes must equal the exact external security object consumed by the authenticated collector. A different valid object is rejected. This carrier is external acquisition metadata; it is not a fifth V2 file or an amendment to a normative schema.

Source rules are acquired and bound as CP4O-S90-SOURCE-RULES-1. Their explicit local interpretation selects exact S90 record IDs, CP2 directory IDs and non-null typed-value presence bits. S90 mandates visible null tags and BOOL presence surfaces; this executable conditional source interpretation is not represented as an independently appointed universal production parser or qualification. A source must independently establish that interpretation for actual use. Unknown/different source grammars fail capability; a field name alone never appoints an interpretation.

All containing bytes are canonically parsed. Every schema directory and every record is shape-validated before publishing an object locator. Record identities are unique and ASCII-sorted, indexed on disk. Per-record primitives, artifact decoded-octet digests and FIELD-CLASS-REF exact register membership retain their existing rules. No malformed later record is hidden by projecting an earlier valid field.

## Projection laws

- A semantic field produces canonical JSON of its typed value plus exactly one LF. Context-valid null produces `null\n`, not empty bytes or fabricated data.
- A literal registered `.$record` class produces the complete canonical record plus LF; identifiers are preserved exactly.
- ROOT format, profile_digest and phase come from the validated wrapper; schema_directory is the complete ordered schema key array.
- Per-schema status and justification come from the actual directory; instance_count and record_directory derive from its complete validated array.
- Presence is the explicitly bound local source grammar's non-null-value bit. A required missing key is rejected before projection. A null field still has its own presence occurrence.
- CP2-REF-PARSER subfields come from a complete typed SOURCE-REF or the exact one-based LIST-SOURCE-REF item, with the parent record and six-digit CP2 reference ordinal joined to the token occurrence. A null reference has no invented child key. If such a child is required, acquisition rejects; qualified guarded actual-occurrence directories must justify absence.

For ASSESSOR-EVENT, all record/field/reference/presence projections require exact correspondence with the independently supplied complete source trace, uniquely matching the event ID and every record value, plus explicit assessor-competence and source-producer-correspondence laboratory prerequisites. Thus READ input_bytes=null is locally shape-valid and usable in a conditional fixture only when that exact source trace says null. READ empty bytes is a distinct valid fixture state when source-owned. CALL/RETURN invocation bytes and results still pass the retained exact assessor/ledger checks. Nothing infers event applicability from the word READ.

ASSESSMENT INVALID/UNAVAILABLE bound null, EXACT OBLIGATION experiment null and UNION COMPOSITION theorem null follow their existing explicit S90 record conditions. These are not generic nullable primitive types. Ordinary BYTES rejects standalone `null\n`. UNAVAILABLE record directories cannot discharge required evidence. INAPPLICABLE requires source justification and its independent validation; byte projection of a status/justification does not establish that validation.

## Demonstrated bypass and correction

An adversarial conditional fixture replaced one non-null CALL field's projection carrier with a CP4L standalone value containing identical canonical bytes. Before the final guard this passed, although containing-record correspondence for that token was bypassed. The actual report is results/4O-before-required-projection.json. The executable mutation is fixtures/projection_mutations.py.

The corrected owning-value path requires containing-object projections for SECURITY, SECURITY-FRAME and CP2-REF-PARSER classes. Equal standalone bytes now fail MISSING-EVIDENCE and cannot establish equality/scopes or ledger budgets. Generated parser/material classes fail INCOMPLETE-EVIDENCE-UNIVERSE until their required containing-event adapters exist. General direct TSEV1/S90 primitive acquisition for other declared source classes remains unchanged. Tests verify the bypass is rejected without weakening any primitive or changing failure ORDER.

## Bounded lifetime and recovery

4N's guarded raw ranges, canonical indexes, bounded four-handle pools and source/digest caches are reused unchanged. Two temporary disk maps hold object locators and record ordinals. No resident map of all record objects or encoded hex is added. Large hex and projected lists stream. The inherited 64KiB byte buffers, 128-level parser depth and 1 MiB ordinary scalar capability remain. To bound the existing LIST-ID uniqueness check, projected records impose a 4 MiB aggregate reference-ID metadata capability before validation; exceeding it yields INCOMPLETE-EVIDENCE-UNIVERSE, never a semantic PASS. Required model/graph/index memory remains separate.

A locator reopen reacquires its exact source reference and rules, rehashes the complete decoded snapshot and reuses 4N's index byte/code/job/receipt checks. Large Node/Hex ranges retain containing-object guards. An exception or pause closes all temporary maps through Store cleanup. Partial containing-object validation cannot publish a complete locator. Across recovery, the small record-locator map is rebuilt from the exact complete object; complete semantic indexes are reused only after byte checks. Equality acquisition is revalidated before a completed equality receipt is reused, with exact byte comparison on hash collisions.

Receipts are CP4O-bound; CP4N jobs must not be silently imported. Preserve input paths, key, checkpoint and all stages. Hashing/reopening may reread the whole containing object and index after eviction, and authentication/native link processing retains exact prefix reconstruction costs. Active cached handles still require the explicit trusted quiescent-execution boundary; permissions, timestamps, locks and possession of journals are not cryptographic identity, source truth or qualification. No partial authentication succeeds.
