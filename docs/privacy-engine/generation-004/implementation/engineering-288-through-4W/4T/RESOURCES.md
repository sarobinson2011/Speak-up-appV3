# Resource plan and uncertainties

No new throughput benchmark ran in this checkpoint. Metadata correspondence took 23.30 s and peaked at 2,171,476 KiB in the construction process; that is not the execution worker's memory. This model check need not run on the user's computer.

Retained 4A text samples: 476–535 MB/s, 5.66–8.88 s for selected 64-rank segments, peak native child RSS 483,584 KiB (472.25 MiB). Each was bounded and is performance evidence only. Their row/byte/first-ordinal results match the new candidate-bound analytical prefix table. The local completed binary job took 4,111.895 seconds for both binary passes; this is not scaled into a textual estimate.

At retained text effective rates, one 19.909 TB pass is about 10.3–11.7 hours. Use the retained conservative planning range **12–24 hours per pass, 24–48 hours for generation plus same-generator replay**, with additional controller/journal overhead and possible slower hardware. These are estimates, not a promised upper bound. A **48-hour aggregate charged review stop** is proposed. If reached, pause with all completed segments retained; an explicit later grant can extend the same job.

A separately labelled `local_probe.py` is available after installation. It runs just two metadata-selected high-byte segments, 16 and 64 ranks, each under a 58-second process timeout (55-second worker timer), at most 116 seconds in aggregate. It reports parent/child RSS separately, rates and planning extrapolations. It creates no execution journal and makes no complete-stream digest claim. A 35-second threshold leaves margin for the 45-second execution slice. Do not launch if neither width fits. No probe was performed on the user's machine from this chat.

Execution is sequential: supervisor, Python slice process and native child. Each inherits a 2 GiB address-space limit (at most 6 GiB combined virtual-address ceilings); host preflight requires **8 GiB effective available RAM**, accounting for cgroup headroom. This is a planning reserve, not a full-model collector memory claim. The descriptor is parsed and its structural set sorted on every native slice; supervisor/controller also rehash the 236.9 MB descriptor and read growing journals. Descriptor I/O benefits from page cache but is not assumed free. Small retained worker RSS is not proof of a universal host bound.

Storage does not scale with 19.91 TB. PACKAGE-MANIFEST.json gives exact delivered bytes and a conservative bound for 60,000 attempts, 26,687 minimum-width segments, serialized log/receipt caps, two rotating backups, a temporary backup, fresh restoration, filesystem allocation and headroom. Host checks require **8 GiB free disk** and sufficient inodes. Typical 64-rank execution should use considerably less (roughly 1–2 GiB including descriptor, journals and backups); the reservation covers allowed retries and 16-rank operation, rather than assuming the fastest plan. Shared system libraries are reused and hash-bound; they are not extracted into the kit. No compiler, Python package installation or model archive chain is needed.

Passes: one text generation and one same-generator replay, hash-only. Each consumes every required serialized byte. No supplied-file read, Ed25519 verification or qualification is performed here. At most one uncommitted native slice is lost on interruption (45-second worker allocation; 50-second outer timeout). Every reservation is durably charged up to 60 seconds if interrupted. Resumption audits journals, rehashes inputs and reconstructs the descriptor index; it does **not** reread or regenerate the previously completed multi-terabyte prefix. Pure Ed25519 prefix reconstruction costs belong to later signed-input work and are not eliminated by this SHA-state recovery.

Power-loss durability depends on a user-controlled filesystem honoring file and directory fsync/rename. Read-only host checks cannot prove that property, future memory/disk availability, or survival of disk failure. Keep verified snapshots on independent storage if protection from device loss is required. Checksums/journals establish local integrity only, not source qualification or authenticity against an adversary who can replace the entire job and its checksum evidence.
