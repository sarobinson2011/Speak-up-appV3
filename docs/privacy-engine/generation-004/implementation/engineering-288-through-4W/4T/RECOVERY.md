# Recovery without restarting completed work

The detached launcher survives ordinary terminal closure and logout when the OS permits the user process to continue. It is not a system service and cannot prevent reboot, power loss or session managers that kill all user processes. Suspend must remain disabled for unattended progress. Use a durable local filesystem; keep the installed kit and runtime libraries unchanged during the run.

`status` and `verify-completion` are read-only metadata audits. `pause` writes a marker; the current bounded slice may finish. Wait for the process to exit before copying a snapshot. Resume the same task path. Every segment is published by file fsync, atomic rename and directory fsync. A lagging HEAD can be reconciled with one fully published contiguous record. Unpublished .part files do not count as completed work. Corrupt or discontinuous records fail; they are not silently skipped.

Ctrl-C/SIGTERM/SIGHUP request a graceful pause in the supervisor. If forcibly killed, an already published child segment remains usable; the outstanding 60-second reservation is charged on resume. A native child can live for up to the 50-second outer deadline after a supervisor loss. Wait at least 60 seconds before resuming after a hard kill; overlapping workers reject the job lock. No command here restarts the binary job or reads its state.

The initial textual budget is 48 hours of charged active processing, including audits within each reserved operation. Downtime is not charged. Review-stop never clears progress. `extend --hours 24` is an explicit additional local authorization, recorded as a chained job-bound grant, and does not itself start work. Resume separately. There is no automatic reset or extension. A 60,000-attempt storage guard remains even after grants.

Generation permits 16-, 32- or 64-rank future slices. `resume --segment-ranks 16` preserves already committed 64-rank segments. Cumulative SHA state and interval continuity bridge mixed widths exactly. Replay retains each committed interval, so shrinking future generation is not a remedy for an already committed interval that becomes unreplayable on a much slower host. Preserve that case for a bounded controller change; never discard the completed generation or mislabel partial replay as complete.

`snapshot.py save` locks the paused supervisor, checks the chains and budget grants, creates a manifest/CRC-checked ZIP and atomically rotates two backup slots. `restore` verifies the external snapshot SHA, exact membership and pinned kit identity, and requires a fresh destination. It restores paused. An interrupted restoration has a RESTORE-INCOMPLETE marker and cannot execute; repeat restoration to another fresh destination using the intact snapshot. Restore changes storage location, not the job/model/contract/runtime identity.

Whole-stream SHA is the final cumulative SHA-256 state rooted in the exact header and advanced through all contiguous rank intervals. Each native invocation also independently checks its expected row count; the supervisor checks exact analytical rows, bytes and first ordinal per interval. Same-generator replay recomputes each interval and compares its bytes count, segment digest, incoming/outgoing cumulative state and prefix digest. Segment digest concatenation is never used. Neither partial progress, a prefix digest nor a snapshot can report a complete identity.

This is recoverable mechanical identity computation, not authentication. Existing actual-input collectors, supplied-row validation, final-profile joins, source appointments, assessor competence and qualification remain outstanding.
