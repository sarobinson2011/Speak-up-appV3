# 4R package verification

4Q's exact saved ZIP and receipt were verified; the selected native executable, controller, descriptor and hashed source dependencies match the retained 4A manifest. Accepted sources, 4I amendment, contract, provisional model and qualification boundaries are unchanged.

Only necessary bounded new package checks were run. They cover the independent four-token exact-byte oracle; generation/replay pause and repeated resume; torn temporary writes; interrupted accounting after a committed native segment; identical terminal results; corrupted/missing records and replay substitution; runtime/plan substitution; persistent review stop; deleted budget state; snapshot restoration and wrong-digest rejection; and read-only preflight rejection of insufficient memory/disk and native incompatibility. The exact recorded output is results/4R-package-checks.json.

The shipped native worker passed six-candidate anonymous-RAM compatibility probes in the build environment. This does not certify Steve's Ubuntu machine. In fact, the cloud's effective cgroup memory headroom does not meet the intended 8 GiB host reservation; no cloud host-preflight PASS or full execution is claimed.

Fresh-extraction byte checks and the bounded package checks are recorded in the external 4R receipt. None of the completed 4P regression suite, full model expansion, full binary/text stream generation/replay or full table hashing was rerun. No throughput benchmark was added. The only emitted pair bytes were tiny independent package oracles inside hash buffers.

The delivered kit has no computed full-stream SHA-256. A successful future local COMPLETION.json will contain the actual computed-and-predicate-replayed SHA-256 with exact row/byte counts and identity bindings, while profile_admitted/actual-admission and qualification remain false.
