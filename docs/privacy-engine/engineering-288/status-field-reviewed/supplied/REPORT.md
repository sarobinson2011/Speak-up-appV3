# Bounded status-field correspondence extension

The existing declaration producer and correspondence validator now bind all six ManagedAuthority.status return fields to their defining source expressions, direct writes, guarded internal argument origins and applicable source transitions in both SYMBOLIC-U-ONE and SYMBOLIC-U-TWO. This is executable static correspondence plus a connection to the saved successful observations, not a new status endpoint, logger or runtime implementation.

## Reused work and intentional changes

The historical compile_bundle, validate_bundle and constructed managed-route consumers remain unchanged in the extended copy of managed_coverage.py. The new compile_status_fields / validate_status_fields entry points consume the existing verified model and producer source inventory. They reuse the inherited phase, epoch and other applicable local declarations; the missing owning-return and field declarations are additive, with no canonical allocation or occurrence ordinal.

The existing correspondence derive body is retained as derive_boundary. Its source/site, contract, basis, duty and two-context mappings remain the base. The new derive and validate connect the field catalogue and saved field projections to that base. Public acceptance remains exact sorted compact UTF-8 JSON with a final LF. This serialization law belongs to the adapter output; it is not an invented serialization law for a Python status dictionary.

The original SOC-02-R1 adapter remains byte-identical and is consumed through its existing load and derive checks. That reuses its source-state, caller, output, close-identity and fixed_status checks, including recovery's actual child frame and exact whole-value embedding equality. No previous test/review suite is called. The new connection adds individual field/declaration/pointer joins and type checks. It does not reconstruct an older incompatible full trace.

The defining source is live_connection.py, 5,717 bytes, SHA-256 7344170ca01a2dbbd3afbeb4a6a55c0b95db0edb1a8d74e4fa4638b6dcfc6da5. Existing guard_relationships and its independent guard_oracle are recovered unchanged from the exact pinned candidate archive. The generator uses parent-edge guard extraction; the oracle independently traverses control-owned subtrees. Their outputs must agree before a status catalogue can be constructed. Required field/write/caller membership is regenerated from the defining AST on every validation, never from a submitted expected list or cached output catalogue. Altered cached source guards cannot override that source.

Origin expressions are typed source trees. They retain literal/selecting expressions, concatenation, exception type/text operands, local capture, conditional branches and exact guards. This exposes, for example, the early return before disposal, the READY recovery refusal, cleanup before opening and validation before the epoch increment. Exception-derived reason content has no finite string bound. The pure expression evaluator used by constructed controls takes already supplied symbolic type-name/text operands; it never calls an exception's __str__, an application method or a backend. Those examples are not historical observations. The declarations preserve exact source text and qualify any later actual text by its own evidence. No blanket public/constant classification follows from these mappings.
