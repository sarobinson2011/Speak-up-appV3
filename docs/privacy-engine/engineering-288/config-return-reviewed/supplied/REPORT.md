## Copy semantics and scope

The executable copy relation represents a finite graph of ordinary builtin dicts with string keys, lists, and immutable scalar leaves. Its node correspondence preserves exact container kinds, key and element order, scalar types/values, internal alias classes and cycles. Mutable nodes reachable from source and copied roots must be disjoint. The relation permits shared immutable leaves and does not invent fresh identity for them. Graph symbols name constructed references, not host addresses or observed connections.

Internal aliases must remain aliases: two references to one nested list in the source map to one copied list, rather than two independent lists. Conversely, distinct equal-valued mutable source nodes cannot be merged. Shallow copies with shared nested mutable nodes reject. A shallow copy of a flat all-scalar dict can satisfy the same value/reference relation as a deepcopy; values alone cannot distinguish those mechanisms. The independently pinned and checked source expression still requires copy.deepcopy, and a submitted shallow-copy origin rejects. This distinction is explicit rather than a claim that flat values prove which copier executed.

The actual valid CONFIG domain has no nested mutable values. Nested and cyclic controls therefore exercise constructor-copy/data semantics before typed readiness, or the pure source-copy relation, and are never relabelled valid READY configurations. Tuples, subclasses, reducers and custom __deepcopy__ methods are outside this executable data projection; the source may encounter them before validation, and no universal isolation or termination claim is made for them. No new numerical bounds or permitted configuration types are introduced.

Constructor input is represented at copy evaluation. A later mutation of that caller-owned input need not match stored configuration. Constructed controls verify storage isolation from such a mutation, and verify that mutating a nested returned copy leaves storage unchanged while preserving aliases inside the returned copy. All three objects alive in an instance-qualified constructed chain must also respect the two distinct copy boundaries. These are constructed facts, not historical observations.
