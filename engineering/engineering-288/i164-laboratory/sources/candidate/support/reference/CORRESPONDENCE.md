## Reading the field table

FIELD-CORRESPONDENCE.csv contains 424 proposed field/framing rows in 41 grouped record families. Every row pins its actual defining source hash, function/branch anchor, existing representation or absence, required change, dependency, authentication and occurrence rule. These are specification names, not registered final surface IDs. SCHEMA-SPEC.json is a machine-readable planning inventory, not a model or executable parser. Repeated occurrences must not be collapsed into those 41 templates. @presence/@availability/@encoding_length/@member_count identify required framing work, not literal implementation members or final framing cardinality.

All proposed classes have unresolved seven-role custody/visibility cells. The lab stores HEAD/events/blobs/journal/ownership locally, returns signed bytes to the executor client, and accepts observations from an observer principal. These are observed code paths, not authority to assign PUBLIC, CONFIDENTIAL or a constant exception. Include recipient, signer, storage/backup/recovery access, response/error, transport and observer auxiliary surfaces under the source-owned coalition model. UNKNOWN is not confidential. Register actual authentication and separately mark source truth/appointment/finality unqualified. Lifecycle labels such as recovery are not new accepted phases. Owning E/PRE-EXECUTION/PRE-COMMITMENT phase assignment must come from the actual occurrence/gate producer; a code branch alone cannot supply it.

## Exact identity and nested correspondence

1. ATTEMPT.ref is SHA256 of canonical original blob bytes created by accounting.record. The immutable fields are binding,pilot,session,u,intent,sid,action,parent,transaction,ordinal,retry_id,request. The initial parent/transaction/retry_id are null by design. Its exact transaction binding is transitive through action.template and subsequent persisted signature; do not mutate the initial blob to fill transaction later. Retry blobs bind that exact signature reference, prior latest attempt, caller retry ID and new global charged ordinal. Original action.attempt_ordinal never changes.
2. ACTION.ref binds version,binding,pilot,session,sid,u,intent,reservation,branch,kind,index,template,decision_request,attempt_ordinal. Template contains signer,chain,nonce,target,calldata,value,gas_limit,gas_price. Keep template strings and actual decoded Ethereum integer fields separately typed with explicit decoder correspondence, not float/bool coercion.
3. Ownership coordinate is SHA256(enc([chain,executor,str(nonce)])); raw row has coordinate and owner; owner=SHA256(enc([kind,binding,u,intent_ref])). SQL coord/raw/hash and parsed members each need a class and exact join. Retire claims the petition coordinate. OPEN atomically claims the full approved union [b,p+2], p=b+n+2. Every subsequent decision/sign/sign persistence/release/retry checks the same permanent owner. Guarded historical signed-carrier reservations share this ledger without migration. There is no free/transfer/renumber transition.
4. Original unsigned intent bytes remain in a blob. Compact identity and full calldata base64 require separate field classes; ABI-derived arguments retain their existing ABI.json/executor abi.py ownership, both methods and nested tuples/arrays. Never substitute a digest for required argument/message bytes. STAGE-META.bindings expands every stage_carrier.KEYS member; authorized_values expands ordered method-specific elements, their exact parser outputs and containing-array links. Public-key/signature/message bytes, address/digest/numeric domains and conditional-comparison capsule remain explicit.
5. Namespace binding preimage must expand config fields, principals map keys/values and retained module map keys/digests, accounting/ownership/authority code identities and shared ledger incarnation. A hash field is not the entire dependency closure. No digest proves exclusive key custody or source truth.
6. Distinguish enc(request) hashes in event/action/attempt/query from SHA256(packet) in response.request. Packet includes request and principal signature. Response envelope includes response and server signature; response contains request,challenge,ok and guarded data/error. Preserve nested method bodies, empty head body, optional attempt on retry result, false release on SIGNED recovery, null query/tx/reconciliation and FAILED-FROZEN.result presence. SQL wrapper fields, lengths, keys, statuses and parse/error observations remain visible surfaces.
7. Bind every dynamic u/transport/retry_ids/backups entry to its containing HEAD/event/returned-state occurrence and exact key. A static class can be shared; two historical occurrences cannot be merged because values match. Blob interning does not identify distinct acquisitions or releases. Preserve raw transaction and decoded RLP/signature fields under signed_eth.py, all original byte references, and raw message projections under stage_carrier.py.

## Transition correspondence

All successful mutations use Authority.transaction BEGIN IMMEDIATE and save with exact expected-head CAS and canonical HEAD/event comparison. The request journal commits first in a separate transaction. Failed actions may retain request/error evidence while leaving HEAD/events/blobs/ownership/counters unchanged. Represent those two persistence boundaries separately.

For both methods begin/append/finalize/abandon/cleanup have the same branch/resource structure. Finalize always charges verifier budget; PROCEED additionally charges verifier for signPetitionWithZKProof only. Each retry of a verifier-capable transaction repeats its conservative verifier charge. The ordinary method must not gain a new ZK prerequisite.

Open abandonment after k accepted appends uses next q=b+k+1, then cleanup q+1. After finalization abandon uses p, cleanup p+1. Normal proceed p then cleanup p+1. After confirmed proceed revert, abandon p+1 then cleanup p+2. Each requires available resources and owned coordinates. UNUSED, pending, SIGNING, unknown PROCEED and successful consumed petition do not authorize abandonment. Finalization is input authentication only. No local stop establishes an abandoned chain state, non-execution or resubmission rights.
