# Finite saved-acquisition construction inputs

This new, separate adapter consumes the reviewed evidence-count component, the
exact 666-member current candidate, the exact 163-member draft connection and
the original saved acquisition/evaluation archives embedded in that component.
It does not overlay any predecessor source.

`finite_inputs.run(component_root, root, draft, submitted=None)` is the public
build/validation boundary. Every call reauthenticates the component and both
trees, derives a fresh expected bundle from the original saved evidence, and
rejects a submitted mismatch before issuing a success result. A matching bundle
must then pass the retained authentication, candidate/procedure and count
validators. Finally the adapter exercises the pinned pure native `pairs()`
function on its generated work groups. All results are detached deep copies.
Use Python `-B` (or `PYTHONDONTWRITEBYTECODE=1`) to preserve strict input trees.

## Occurrence mapping

For each context independently, directories retain their source order and each
directory's local occurrence IDs sort lexically. Local token indexes run from
zero within that context only. Keys are the full tuple
`[acquisition_id, context, pinned_local_occurrence_id]`; equal bytes do not merge
keys. Each token retains its exact bytes, declaration source/selector/guard,
original projection link or framing owner, and UNKNOWN qualification.

All directory entries remain present, including empty ranges. A snapshot-local
empty range does not replace the source's unresolved production cardinality.
The full original authenticated export bytes are included in the bundle.

## Relations and native interface correspondence

Structural joins independently enumerate the compiler's exact FRAMING-OWNER,
SAME-OBSERVED-VALUE and NEAREST-DECLARED-ANCESTOR selection laws. Each present
source must resolve exactly one target. Twelve n-ary authenticated-fold
obligations remain endpoint sets with `pair_count: null`; they are not extra
Cartesian edges.

Semantic pairs reuse the reviewed `semantic.View` and `_pairs` source selectors
over the authenticated fold. Their source ordinal/record/pointer ordering is
preserved. Structural serialization uses ordinal then source occurrence ID;
this is a local bundle ordering, not a newly adopted historical stream order.

Each relation has a role-separated native lookup work group. A source row is
`[context_local_index, JSON([ordinal, source_key, target_key]), JSON(target_key), true]`.
A target row is `[context_local_index, JSON(target_key), null, true]`. These
implement the retained `Group.entries/get/parts` contract and are consumed as
PARENT-RECORD lookups with `old_rel_n = 0` in an isolated single-rule plan. This
mechanical encoding does not classify semantic associations as containment.
Rule kinds, guards, source anchors and original ordinals remain attached.
Cartesian substitution is rejected, even where it accidentally gives the same
small count. No global or historical token offset is allocated.

The exact `prepare(parent, base)` and `build(p)` source/signature/AST identities
are checked against the draft's native-target declarations, without importing
either module. The generated bundle is an explicit prospective input contract,
not a value that can be passed directly to these historical builders. Only the
previously reviewed extraction of the pure `pairs()` function is executed.
`expected_counts`, `descriptors`, builders, verifiers and ledger rebinding do not
run. Historical arrays, model identities and relation ordinals are not rewritten.

## Duty and acceptance boundaries

Per-relation finite counts, per-directory ranges, the retained procedure result,
native duty names and all eleven obligations are preserved. The top-level
`native_duty_names` is the common duty set for every directory range, matching
the retained `prospective_procedure.count_only()` per-directory templates. It
does not assert that any duty has been discharged. Classification is
UNKNOWN; qualification UNAVAILABLE; disposition NOT-ESTABLISHED. The snapshot
has no derived array-index records; such a changed acquisition explicitly
rejects at this adapter boundary rather than inheriting unsupported coverage.

No full lifetime universe, production storage bound, current native model,
qualified ledger, canonical registration, readiness or admission is established.
Decision B and the unapproved retention/compaction boundary remain unchanged.

The API's underscore-prefixed helpers produce provisional data only. They are
not public evidence-validation or receipt entry points. Successful acceptance
requires `run` or the CLI. Ordinary JSON serialization is validated afresh;
there are no cached success objects or caller-supplied expected counts.
